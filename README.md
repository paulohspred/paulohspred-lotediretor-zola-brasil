# LoteDiretor Brasil

LoteDiretor Brasil is a territorial and urban-engineering decision platform. The current application preserves the proven ZoLa map experience as a city-lab frontend while the versioned Platform v2 Data Plane is introduced incrementally.

The active laboratory municipality is São Paulo. The main product surface is **Plano Diretor**, which combines cadastral identity, zoning/context evidence and reproducible terrain analysis.

## Current architecture

- **Web:** Ember/ZoLa-derived SPA served by `server/production.js` and supervised by `lotediretor-web.service`.
- **Platform API:** NestJS + Fastify + GraphQL/OpenAPI in `platform-v2/services/platform-api`.
- **Data Plane:** PostgreSQL/PostGIS, MinIO, Martin, Valkey and NATS via Docker Compose.
- **Workers:** property/evidence materialization and independent terrain materialization.
- **Evidence model:** source registry, immutable source snapshots, citations, provenance and quality assessments.
- **Terrain product:** MDT/TIN/1 m grid, slopes, contours, profiles, drainage screening and street-grade/access screening (`terrain-surface-v5`).

## Requirements

For the legacy frontend use Node.js 22 LTS and Yarn 1.x. Platform v2 containers use Node.js 22+.

## Development

```bash
git clone git@github.com:paulohspred/paulohspred-lotediretor-zola-brasil.git
cd paulohspred-lotediretor-zola-brasil
yarn install --frozen-lockfile --ignore-engines
yarn start
```

Platform v2 local foundation:

```bash
cd platform-v2
cp .env.example .env
sudo docker compose -f infra/docker/compose.yaml --env-file .env up -d postgres valkey nats minio martin
sudo docker compose -f infra/docker/compose.yaml --env-file .env --profile migrate run --rm migrate-platform
sudo docker compose -f infra/docker/compose.yaml --env-file .env --profile bootstrap run --rm minio-init
```

The values in `.env.example` are development placeholders. Shared/staging/production environments must use private credentials and must never commit `.env`.

## Production operations

The web process is owned by systemd. Use `scripts/deploy-production.sh`; do not start another Node process with `nohup`.

Platform backups are generated by `scripts/backup-platform-v2.sh` and scheduled by `lotediretor-backup.timer`. Backups include PostgreSQL custom-format dumps, MinIO object mirrors and SHA-256 verification.

## Technical limitation

MDT-derived topography, drainage and street/access results are screening/analysis products. They do not replace cadastral/topographic field survey, hydraulic design, legal frontage determination, roadway approval or executive engineering design.
